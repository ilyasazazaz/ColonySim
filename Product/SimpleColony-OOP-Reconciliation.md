## Что изменилось в облаке

1. Состояние вынесено в Entities.cs: отдельные Profession, Resource, Activity, Deposit, Inventory. CargoType теперь независим от профессии, поэтому перевод не перекрашивает уже переносимый груз.
2. Navigation.cs содержит Pathfinder и TravelPolicy. Стоимость питания и сил проверяется перед переходом; маршрут назначения учитывает возвращение.
3. ProfessionBehaviors.cs вводит Strategy через IProfessionBehavior. Добыча разных ресурсов использует общую параметризованную стратегию.
4. Research.cs добавляет пять исследований с тремя уровнями.
5. Добавлены найм, безработные, изменение численности профессий, удержание для описаний и статистика FPS/TPS. Защитники резервируют очаги и остаются на постах.
6. MapGraphic использует геометрию Canvas, кольца ресурсов, жесты и окраску дорог. Интерфейс имеет раскладки для двух ориентаций.
7. Добавлены SimulationValidation и InterfaceValidation. Последняя проверяет события ввода; видимость геометрии она не доказывает.

## Целевая структура

Один значимый класс на файл. Имена файлов совпадают с классами. Короткие XML-комментарии объясняют ответственность и ограничения. Сценарий запуска и создания объектов находится в одном Composition Root — ColonyBootstrap.

```text
SimpleColony/
  Domain/
    World/       WorldGraph, Territory, Road, ResourceDeposit
    Colonists/   Pawn, PawnNeeds, PawnMovement, Cargo, ProfessionDefinition
    Colony/      Inventory, ResearchProgress
    Jobs/        JobAssignment, WorkReservation, IProfessionBehavior, стратегии
  Application/
    SimulationSession, SimulationClock, JobCoordinator, NavigationService
    Commands/    ConvertPawnCommand, RecruitPawnCommand, SetAccessCommand
    Modules/     IMechanicModule, ModuleRegistry, SimulationConfiguration
  Mechanics/
    Threats/     ThreatModule, ThreatService, ThreatRules
    Research/    ResearchModule, ResearchService, ResearchRules
  Presentation/
    Map/         MapPresenter, MapGraphic, MapCameraController
    HUD/         SelectionPresenter, SelectionPanel, ProfessionCard
                 WorkforcePanel, ResearchPanel, HelpPanel, DiagnosticsPanel
    Styling/     ColonyTheme, IconLibrary
  Unity/
    ColonyBootstrap
```

Domain не ссылается на Unity, Canvas и MonoBehaviour. Presentation читает модель и отправляет команды Application. Composition Root создаёт зависимости обычными конструкторами, после чего передаёт их объектам. Глобальный Service Locator не нужен.

## Объекты и инкапсуляция

- Territory владеет коллекциями дорог и залежей. Соединение территорий проходит через WorldGraph.Connect, который проверяет симметрию, отсутствие повторов и лимиты генератора.
- ResourceDeposit разрешает изменение количества только через Take/Regenerate; Inventory — через TrySpend/Deposit. Отрицательные и нечисловые значения отклоняются.
- Pawn владеет потребностями, грузом, движением и текущим заданием. Мутации выполняются методами Pawn, PawnNeeds, Cargo, PawnMovement с проверкой инвариантов. Массовых internal set не оставлять.
- JobAssignment представляет назначение и владеет WorkReservation. Завершение, отмена, смерть и смена профессии освобождают резерв ровно один раз. Резерв относится к виду работы и ресурсу, а не только к территории.
- NavigationService возвращает объект Route с дорогами и расчётом стоимости туда/обратно. TravelPolicy используется и для выбора пути, и для списания, и для цвета дороги.
- Состояния пешки представлены IPawnState: Idle, Moving, Working, Resting, Dead. Контекст PawnController управляет переходами и освобождением задания; каждое состояние имеет отдельную ответственность. Смена профессии использует Strategy, а не изменение наследуемого типа пешки.
- Иерархии использовать там, где есть заменяемое поведение: стратегии профессий, состояния пешки, модули. Общий базовый класс для всех объектов мира не вводить без общего поведения и инвариантов.

## Паттерны с конкретным назначением

| Паттерн | Применение |
| --- | --- |
| Strategy | Профессии и сменяемые правила стоимости пути. |
| State | Переходы поведения пешки с явными условиями входа/выхода. |
| Command | Действия игрока, общая валидация и результат с причиной отказа. |
| Observer | События изменения склада, выбора и профессии обновляют соответствующие панели. Отписка при уничтожении представления. |
| Factory / Composition Root | Создание сеанса и выбранных модулей с явной передачей зависимостей. |
| MVP | Панель отображает данные; presenter обрабатывает выбор и вызывает команды; игровая модель не знает о UI. |

## Подготовка модулей

Первая практическая граница — независимо включаемые ThreatModule и ResearchModule. Переключатель в меню пока не реализуется: он следующий этап после рефакторинга.

- SimulationConfiguration хранит seed, правила темпа и список выбранных ModuleId. Базовая генерация, перемещение, склад и пешки составляют ядро сеанса.
- IMechanicModule предоставляет стабильный Id, требования и методы установки/завершения. Установка регистрирует конкретные службы и поведения; процесс не должен сводиться к if(moduleEnabled) внутри World.Step.
- ModuleRegistry проверяет уникальность, зависимости и порядок до создания мира. SimulationSession выполняет упорядоченные шаги зарегистрированных механизмов.
- ThreatModule создаёт очаги, распространение и задания защиты. Без него нет очагов и связанных заданий.
- ResearchModule создаёт прогресс исследований и правила покупок. Без него UI не предлагает недоступные исследования; навигация получает базовые параметры без знания о модуле исследований.
- Эффекты исследований передаются через настройки/политики движения, груза и восстановления. ThreatModule не обращается непосредственно к ResearchModule.
- UI получает описание доступных команд/механик и скрывает соответствующие панели по возможностям сеанса.
- Первый вариант выбирает состав при запуске новой игры. Отключение механик посреди сеанса, загрузка DLL, моддинг и миграция сохранений в эту подготовку не входят.

## Порядок переноса и проверка

1. Зафиксировать поведение облачной версии: выполнить SimulationValidation; отдельно скомпилировать Unity-скрипты. Проверить пустую карту в Play Mode.
2. Извлечь сущности и ограничения без изменения баланса, seed и порядка обновления. Затем вынести навигацию, назначения и состояния пешек.
3. Сформировать SimulationSession и Composition Root; подключить угрозы и исследования через два модуля с включением по умолчанию.
4. Разделить ColonyView на presenters, панели, тему и камеру. Объединить визуальный стиль с сохранёнными функциями облака.
5. Проверить исходную конфигурацию, каждый модуль отдельно, оба вместе, отсутствие обоих. Ошибки конфигурации выявлять до старта.
6. В Play Mode проверить видимость узлов/дорог/пешек сразу после запуска, рост графа, повторный запуск после компиляции, касания/перетаскивание, масштабирование, паузу, справку и обе ориентации. Android-жесты окончательно проверяются на устройстве.

Критерий читаемости: по дереву файлов человек находит место изменения конкретной механики, не читая World целиком; UI не меняет поля модели; новая механика подключается в одном месте сборки сеанса.
