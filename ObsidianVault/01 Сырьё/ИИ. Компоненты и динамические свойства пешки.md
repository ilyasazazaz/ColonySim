Материал ИИ. В вопросе из заметки смешаны два значения: модуль игрового опыта и компонент отдельной сущности. Модуль может регистрировать типы компонентов и правила их обработки; наличие модуля не означает, что каждый компонент постоянно хранится в каждой пешке. Это предлагаемое разграничение терминов ColonySim. ^001

В RimWorld XML `ThingDef` задаёт свойства типа, а `ThingComp` создаётся у конкретного экземпляра `ThingWithComps` по списку компонентов в определении. Компонент может хранить изменяемое состояние и участвовать в сохранении. Документация описывает также `DefModExtension` для дополнительных статических полей определения. Следовательно, один мод может расширить тип пешки, не превращая каждое её динамическое свойство в отдельный тип сущности. [ThingComp](https://rimworldwiki.com/wiki/Modding_Tutorials/ThingComp), [способы изменения Def](https://rimworldwiki.com/wiki/Modding_Tutorials/Modifying_defs). ^002

В Minecraft Java Fabric API позволяет прикреплять данные к отдельным сущностям; сохранение и передача по сети настраиваются через кодеки. NeoForge также различает зарегистрированный `EntityType` и экземпляр `Entity` с собственными данными. Эти примеры показывают, что тип, расширяемое состояние экземпляра и его синхронизация являются разными задачами. [Fabric Data Attachments](https://docs.fabricmc.net/develop/serialization/data-attachments), [NeoForge Entities](https://docs.neoforged.net/docs/1.21.5/entities/). ^003

У Factorio другое полезное разграничение: прототипы формируются при запуске, а текущие данные мода хранятся отдельно в сериализуемом `storage` во время игры. Изменение набора модов и версий проходит через загрузку сохранения и миграции. Это предостерегает от идеи менять определение типа прямо во время тика, когда часть пешек уже создана. [Жизненный цикл](https://lua-api.factorio.com/latest/auxiliary/data-lifecycle.html), [хранилище](https://lua-api.factorio.com/latest/auxiliary/storage.html). ^004

Для ColonySim нужно выбрать, какие факты о пешке авторитетны, какие свойства вычисляются из этих фактов и [[03 Структура/Разбор пешки и модулей#^008|групповой статистики]], а какие служат временным кэшем. При смене [[03 Структура/SystemModulationLevels (SML)|уровня детализации]] система должна материализовать необходимые свойства без противоречия уже установленным фактам и уметь сохранить результат. Для мода надо определить идентификатор компонента, схему данных, обработчики событий, стоимость пересчёта, правила отсутствующего компонента и миграцию схемы. Это проектное предложение, требующее прототипа. ^005

История о том, что в таверне Dwarf Fortress слушатели запоминали родословную и это стало конкретным инцидентом оптимизации, пока не подтверждена. [Трекер ошибок Dwarf Fortress](https://dwarffortressbugtracker.com/view.php?id=8584) обсуждает проблемы общения и выбора собеседника, но не указанный механизм. Не следует выводить из пересказа конкретную асимптотику. Для собственного теста можно измерить распространение одного факта среди разного числа слушателей и сравнить личные копии сведений с общей записью и ссылками на неё. ^006
