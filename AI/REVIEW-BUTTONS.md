# Общие кнопки согласования

Единственный редактируемый исходник: AI/review-buttons.js. Исполнитель копирует его без изменений в ObsidianVault/90 Служебное/review-buttons.js: JS Engine читает файлы внутри vault, AI находится за его пределами. Это одна рабочая копия на весь vault, не копии на заметку. Перед развёртыванием и после обновления сравнить SHA256 исходника и копии. Исправлять исходник в AI, затем синхронизировать копию.

Нужен включённый JS Engine. Meta Bind для этого варианта не требуется; не менять и не удалять другие плагины. Если зависимости нет, исполнитель устанавливает JS Engine штатным способом и проверяет его доступность. Пустая папка плагина не означает установку.

В начало тела каждой производной 02–04, после YAML, вставить ровно одну панель:

````md
<!-- review-panel:start -->
```js-engine
const path = "90 Служебное/review-buttons.js";
const target = await engine.internal.getContextForMarkdownCallingJSFile(context.file.path, path);
await engine.internal.executeFile(path, {context: target, component, container});
```
<!-- review-panel:end -->
````

В конец тела той же заметки добавить один блок свойств:

````md
<!-- review-properties:start -->
```js-engine
const path = "90 Служебное/review-buttons.js";
const target = await engine.internal.getContextForMarkdownCallingJSFile(context.file.path, path);
await engine.internal.executeFile(path, {
  context: target, component, container,
  contextOverrides: {args: {mode: "properties"}}
});
```
<!-- review-properties:end -->
````

Нижний блок свёрнут по умолчанию и читает актуальные свойства из YAML, без второй копии данных. Верхнее отображение YAML скрывается настройкой Obsidian «Редактор → Свойства в документе → Скрытые». Не переносить YAML в конец. Панели не добавляются в сырьё. Не вкладывать авторский текст между служебными маркерами. Старые панели заменять, а не дублировать.

Контекст создаётся документированным getContextForMarkdownCallingJSFile: содержит реальный файл заметки и JS-файл. Не конструировать context вручную и не брать активную вкладку. Это устраняет прежний неверный способ передачи контекста, но работа в интерфейсе всё равно требует проверки.

Кнопки сохраняют статус, время UTC с Z, контрольную сумму редакции и историю; «Нужны правки» сохраняет дату прошлого согласования. Повторное согласование той же редакции не добавляет событие. decision_status не меняется. Чужая правка между чтением и записью отменяет сохранение. Открытие панели ничего не записывает.

review-v2 — алгоритм reviewed_revision только для согласования, не автоматическая миграция source_revision. Исключает YAML и явно размеченные служебные панели, нормализует пробелы прозы и технические якоря; кодовые блоки сохраняет после нормализации переносов. Заголовки и журнал правок считаются содержимым. Старый или неизвестный формат требует повторной человеческой проверки; агент не пересчитывает approved-версию за человека. Изменение цели ссылки с тем же видимым текстом не считается изменением текста: корректность источников отдельно проверяет агент.

## Проверка перед объявлением готовности

Запустить `node AI/review-buttons.test.cjs` из корня репозитория. Проверка использует подмену Obsidian API, не меняет vault и не заменяет UI-тест.

На временной заметке в 02 с тестовыми свойствами проверить чтение и Live Preview: две кнопки сверху, раскрывающиеся свойства внизу; клик «Согласовать» меняет статус/дату/историю именно этой заметки, даже если открыта другая; повторный клик не добавляет событие; правка текста показывает устаревание; «Нужны правки» сохраняет прежнюю дату. Не использовать реальные материалы для тестового согласования. Проверить повторное открытие и отсутствие ошибок JS Engine. При недоступном интерфейсе честно сообщить «логика проверена, UI не проверен», не объявлять кнопки рабочими.

Агент 1 развёртывает общую копию и панели своего уровня, агент 2 — панели 03, агент 3 — панели 04. Все используют этот шаблон. Обновление панели не даёт права менять авторский текст или человеческое согласование. Не блокировать текстовую обработку отсутствием UI-проверки.
