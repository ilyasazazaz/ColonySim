# Общие кнопки согласования

Контракт версии 2026-10-10T00:11:51+03:00. Четыре действия реализованы и покрыты изолированными тестами. Мастер отвечает за общий код, тесты и рабочую копию. UI в Obsidian пока не проверен.

Требуются четыре действия: «Согласовать», «Исправлено мной», «Нужны правки», «Отменить действие». Точное поведение, опорные коммиты и авторство обратной связи определены в WORKFLOW.md. Отмена возвращает предыдущее состояние проверки, сохраняет текст и комментарий и записывается в историю. «Нужны правки» создаёт/открывает «Для ИИ» без отправки сообщения. При «Исправлено мной» сохраняются время, проверенная редакция и конкретная база Git; автоматический коммит кнопкой не требуется.

Единственный редактируемый исходник: AI/review-buttons.js. Мастер копирует его без изменений в ObsidianVault/90 Служебное/review-buttons.js: JS Engine читает файлы внутри vault, AI находится за его пределами. Это одна рабочая копия на весь vault, не копии на заметку. Перед развёртыванием и после обновления сравнить SHA256 исходника и копии. Исправлять исходник в AI, затем синхронизировать копию.

Нужен включённый JS Engine. Meta Bind для этого варианта не требуется; не менять и не удалять другие плагины. Если зависимости нет, исполнитель устанавливает JS Engine штатным способом и проверяет его доступность. Пустая папка плагина не означает установку.

В начало тела каждой производной 02–04, после YAML, вставить ровно одну панель:

````md
<!-- review-panel:start -->
```js-engine
const path = "90 Служебное/review-buttons.js";
const target = await engine.internal.getContextForMarkdownCallingJSFile(context.file.path, path);
await engine.internal.executeFile(path, {context: target, component, container});
```
<!-- review-panel:end -->
````

Свойства доступны в боковой панели. Нижний блок review-properties не добавлять, существующий удалить без потери YAML и истории. Кнопки остаются сверху. В конце — один нейтральный блок «Для ИИ», отделённый горизонтальными линиями и явными служебными маркерами; его текст сохранять при смене/отмене статуса.

Контекст создаётся документированным getContextForMarkdownCallingJSFile: содержит реальный файл заметки и JS-файл. Не конструировать context вручную и не брать активную вкладку. Это устраняет прежний неверный способ передачи контекста, но работа в интерфейсе всё равно требует проверки.

Кнопки сохраняют статус, время UTC с Z, контрольную сумму редакции и историю; «Нужны правки» сохраняет дату прошлого согласования. Повторное согласование той же редакции не добавляет событие. decision_status не меняется. Чужая правка между чтением и записью отменяет сохранение. Открытие панели ничего не записывает.

Текущая реализация review-v3 — алгоритм reviewed_revision только для согласования, не автоматическая миграция source_revision. Исключает YAML, явно размеченные служебные панели и блок review-feedback, нормализует пробелы прозы и технические якоря; кодовые блоки сохраняет после нормализации переносов. Заголовки и журнал правок считаются содержимым. Старый или неизвестный формат требует повторной человеческой проверки; агент не пересчитывает approved-версию за человека. Изменение цели ссылки с тем же видимым текстом не считается изменением текста: корректность источников отдельно проверяет агент.

## Проверка перед объявлением готовности

Запустить `node AI/review-buttons.test.cjs` из корня репозитория. Проверка использует подмену Obsidian API, не меняет vault и не заменяет UI-тест.

На временной заметке в 02 с тестовыми свойствами проверить чтение и Live Preview: четыре действия сверху, отсутствие нижнего блока свойств, сохранность YAML; клик «Согласовать» меняет статус/дату/историю именно этой заметки, даже если открыта другая; повторный клик не добавляет событие; правка текста показывает устаревание; «Нужны правки» сохраняет прежнюю дату. Также проверить «Исправлено мной» с сохранением базы Git, обнаружение последующих правок, отмену без потери текста/комментария, повторное открытие «Для ИИ» без дубликатов и отсутствие отправки сообщений. При отсутствии достоверной базы Git не выдумывать SHA: явно сообщить о невозможности привязки. Не использовать реальные материалы для тестового согласования. Проверить повторное открытие и отсутствие ошибок JS Engine. При недоступном интерфейсе честно сообщить «логика проверена, UI не проверен», не объявлять кнопки рабочими.

Мастер развёртывает общую копию. Агент 1 устанавливает панели 02, агент 2 — панели 03, агент 3 — панели 04. Дефект общего скрипта направлять мастеру; не перекладывать его на агента 1. Все используют этот шаблон. Обновление панели не даёт права менять авторский текст или человеческое согласование. Не блокировать текстовую обработку отсутствием UI-проверки.

## Метаданные и комментарий

«Исправлено мной» требует agent_revision с полным SHA из 40 символов и agent_revision_path с путём Markdown-файла относительно репозитория. Исполнитель до установки панели проверяет существование этой редакции через Git. Кнопка сохраняет их как review_base_commit/review_base_path; сама Git не запускает. Базу нельзя выдумывать или заменять текущим HEAD без проверки.

review_undo — служебная JSON-строка с предыдущим и полученным состояниями проверки. Отмена одношаговая, работает после повторного открытия; не отменяет редактирование текста и не удаляет историю. Если человек вручную изменил состояние проверки после клика, отмена отказывается его затирать. review_history — список событий. Отсутствующее или пустое значение допускается; неверный тип не исправляется с потерей данных.

Один блок обратной связи в конце:

```md
<!-- review-feedback:start -->
---
## Для ИИ


---
<!-- review-feedback:end -->
```

Если «Для ИИ» уже есть, исполнитель обрамляет существующий блок этими маркерами, сохраняя комментарии. Кнопка не угадывает границы неразмеченного блока и не создаёт дубликат. Повторный клик «Нужны правки» открывает существующий комментарий без нового события. Отмена сохраняет этот блок. Маркеры внутри авторских кодовых примеров не считаются служебными областями. Повреждённые границы вызывают явную ошибку без записи.

Обновление панели не означает полной проверки заметки: rules_version менять только после проверки всей заметки. Старые reviewed_revision/формат, статус и даты не мигрировать от имени человека. review-v3 не меняет алгоритм source_revision. При старом формате панель показывает необходимость повторной проверки.
