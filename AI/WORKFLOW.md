# Рабочий процесс

## Git

1. Обновить локальный `main`.
2. Создать отдельную ветку: `feat/...`, `fix/...`, `docs/...`, `refactor/...`, `chore/...` или `experiment/...`.
3. Делать небольшие логические коммиты в формате Conventional Commits.
4. Запустить применимые проверки и просмотреть полный diff.
5. Открыть draft Pull Request с описанием цели, решения, рисков и проверок.
6. После проверки выполнить squash merge в `main` и удалить рабочую ветку.

Прямые push и force-push в `main` не используются.

## Несколько людей и агентов

- Одна задача принадлежит одной ветке и одному основному исполнителю.
- Параллельная работа ведётся в разных ветках или Git worktree.
- Перед изменением общих файлов проверить активные PR, чтобы не создавать конфликтующую редакцию.
- Передача работы происходит через описание PR: что сделано, что проверено, что осталось и какие решения требуются.
- GitHub Issues содержат задачи и критерии приёмки; `AI/STATUS.md` содержит только общий этап, а не список всех задач.

## Работа с контекстом

- Устойчивый подтверждённый факт обновляет `AI/CONTEXT.md`.
- Изменение процесса обновляет `AI/WORKFLOW.md` и при необходимости `AGENTS.md`.
- Изменение этапа или ближайшего результата обновляет `AI/STATUS.md`.
- Игровой дизайн, требования и исследования обновляют каноническую заметку в `ObsidianVault/`.
- Не сохранять историю разговоров целиком. Сохранять решение, основание и последствия.

## Обучение по редактуре владельца

- При чтении Obsidian-заметки сначала проверить статусный тег в свойстве `tags`.
- Ровно один из тегов `ИИ`, `источник`, `редактировано`, `подтверждено` обозначает состояние рецензирования заметки. Эти теги взаимоисключающие.
- Для тега `ИИ` считать заметку агентским черновиком без редакторского одобрения владельца.
- Для тега `источник` считать содержательный текст прямым материалом владельца; добавленные агентом ссылки не меняют происхождение заметки.
- Для `редактировано` и `подтверждено` до выводов посмотреть `git diff -- <file>` и `git log --follow -p -- <file>`.
- Найти последнюю доступную версию с тегом `ИИ` и сравнить её с редактурой владельца.
- Различать правку языка, изменение структуры, изменение смысла и явное подтверждение решения.
- Тег `редактировано` является свидетельством личной правки, но не подтверждает автоматически весь оставшийся текст.
- Тег `подтверждено` является решением владельца в пределах содержания, которое он действительно просмотрел и утвердил.
- Повторно применимые выводы записывать в `AI/OWNER_MEMORY.md` со ссылкой на файл и Git-основание.
- Не обобщать единичную правку на весь проект без дополнительных свидетельств.
- Если исходная агентская версия отсутствует в Git, прямо отметить отсутствие базы сравнения и не реконструировать изменения по памяти.

## Авторство

GitHub-интеграции могут записывать автором подключённый аккаунт. Участие агента отмечается в описании PR или пользовательским trailer `Assisted-by: <agent>`. `Co-authored-by` используется только для реального аккаунта с принадлежащим ему email.

## Definition of Done

- запрос и критерии приёмки выполнены;
- отсутствуют случайные и несвязанные изменения;
- применимые тесты и проверки пройдены либо явно указано, почему они недоступны;
- документация обновлена вместе с изменением поведения;
- PR содержит понятный итог и известные риски;
- в репозиторий не попали секреты, кэши или персональное состояние инструментов.
